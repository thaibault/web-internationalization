Project Status

Use case

Translate a website directly in the browser without a build step, server or translation files. Write the translations right next to the original text, mostly as HTML comments, and wrap the page into the "web-internationalization" web component. It switches all texts when a visitor clicks a language link, remembers the choice and picks a fitting language on the first visit.

Quick start

Load the bundle, which contains all dependencies, register the component and add a few styles that hide the translations not shown:

<script type="module">
    import {
        api
    } from 'https://unpkg.com/web-internationalization@latest/dist/bundle/index.js'

    api.register()
</script>
<style>
    lang-replacement, lang-alternative:not([active]), .wi-hide {
        display: none;
    }
</style>

<web-internationalization>
    <a href="#lang-enUS">English</a>
    <a href="#lang-deDE">Deutsch</a>

    <p>
        Welcome to my website.
        <!--deDE:Willkommen auf meiner Webseite.-->
    </p>
</web-internationalization>

Instead of calling "api.register()" you can also set "window.AUTO_DEFINE_WEB_INTERNATIONALIZATION = true" before the script is loaded. "api.register('my-translator')" registers the component under another tag name.

With a package manager

npm install web-internationalization core-js

The default entry point additionally needs its optional peer dependencies "clientnode" and "web-component-wrapper". The bundle variant "web-internationalization/bundle" already contains them:

import {api} from 'web-internationalization'
// Or without further dependencies:
// import {api} from 'web-internationalization/bundle'

api.register()

Older browsers

The default variants target browsers supporting ES6 classes. For older browsers use "web-internationalization/compatible" or the bundle "web-internationalization/bundle/compatible" ("dist/bundle/compatible/index.js" on a CDN) and load the web components polyfill before.

Writing translations

The component only translates content inside its own tag. Each language is written as a code of two lowercase and two uppercase letters, like "enUS", "deDE" or "frFR".

Text with comments

Put a comment starting with the language code and a colon right behind a text:

<p>
    Your English version.
    <!--deDE:Ihre deutsche Variante.-->
    <!--frFR:
        Votre version française.
    -->
</p>

A comment with a leading "|" translates the next element containing text instead. This is handy for headings and elements which should stay clean:

<!--|deDE:Ihre deutsche Variante.--><!--|frFR:Votre version française.-->
<p>Your English version.</p>

Text with markup

A comment only replaces the single text node in front of it. To translate text containing elements, wrap it into "lang-replace":

<p>
    <lang-replace>
        Your English version with <strong>markup</strong> inside.
    </lang-replace>
    <!--deDE:Ihre deutsche Variante mit <strong>Auszeichnung</strong>.-->
    <!--frFR:Votre version française avec <strong>balisage</strong>.-->
</p>

Instead of comments you can also use "lang-replacement" elements, so that editors and tools treat the translations as regular markup:

<p>
    <lang-replace>
        Your English version with <strong>markup</strong> inside.
    </lang-replace>
    <lang-replacement>deDE:
        Ihre deutsche Variante mit <strong>Auszeichnung</strong>.
    </lang-replacement>
    <lang-replacement>frFR:
        Votre version française avec <strong>balisage</strong>.
    </lang-replacement>
</p>

Alternatives

Replacements move content around in the DOM. If scripts or styles rely on stable elements, write each language as its own "lang-alternative" element. The one without a "lang" attribute holds the default language. Only the element of the current language gets the "active" attribute and is shown:

<p>
    <lang-alternative>Your English version.</lang-alternative>
    <lang-alternative lang="deDE">Ihre deutsche Variante.</lang-alternative>
    <lang-alternative lang="frFR">Votre version française.</lang-alternative>
</p>

Reusing known translations

Generated content like a table of contents repeats texts which are translated elsewhere already. Mark such areas with the class "web-internationalization-generated-content" and every text in them which exactly matches an already translated text is switched as well:

<ul class="web-internationalization-generated-content">
    <li><a href="#introduction">Introduction</a></li>
</ul>

<h2 id="introduction">
    Introduction<!--deDE:Einführung--><!--frFR:Présentation-->
</h2>

Texts ending with the template delimiter "}}" are left untouched, so templates rendered later on the client keep working.

Switching the language

Every link inside the component pointing to "#lang-" followed by a language code switches to that language. The link of the current language gets the class "current", so you can highlight it with CSS:

<a href="#lang-deDE">de</a>
<a href="#lang-enUS">en</a>
<a href="#lang-frFR">fr</a>

Without a configured "selection" these links also define which languages are allowed. If you add links later, bind them with "refreshLanguageButtonDomNodesBinding()". You can also switch from code:

const translator = document.querySelector('web-internationalization')

translator.refreshLanguageButtonDomNodesBinding()
await translator.switch('deDE')
console.log(translator.currentLanguage)

Initial language

On the first render the language is taken from the "initial" option, else from the visitor's last choice saved in the local storage, else from the browser language and finally from the "default" option ("enUS"). Common spellings like "de", "de-DE" or "german" are mapped to their language code, unknown ones fall back to the default.

Configuration

Pass options as a JavaScript object in the "options" attribute:

<web-internationalization
    options="{default: 'deDE', selection: ['deDE', 'enUS'], useEffect: false}"
>
    ...
</web-internationalization>
  • "default": Language of the original texts and the fallback, "enUS" by default.
  • "initial": Language to start with, overrides the automatic detection.
  • "selection": Allowed languages. Switching to others is ignored.
  • "useEffect": Fades changed texts out and in, "true" by default.
  • "languageMapping": Alternative spellings per language code.
  • "languageHashPrefix": Link prefix of language links, "lang-" by default.
  • "currentLanguageIndicatorClassName": Class of the current language link, "current" by default.
  • "selectors.knownTranslation": Selector of areas reusing known translations.
  • "templateDelimiter": Delimiters of client side templates, "{{" and "}}" by default.

Events

"onSwitch" runs before and "onSwitched" after switching to another language, both get the old and the new language. "onEnsure" and "onEnsured" get the language when the current one is applied again, e.g. on the first render. "onSwitch" and "onEnsure" may return a promise, the texts are replaced after it resolved. Set them as properties or as attributes, where "parameters" holds the arguments:

<web-internationalization
    on-switched="document.documentElement.lang = parameters[1].substring(0, 2)"
>
    ...
</web-internationalization>

document.querySelector('web-internationalization').onSwitch =
    async (oldLanguage, newLanguage) => {
        await loadFonts(newLanguage)
    }
